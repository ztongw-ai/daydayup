# DAYDAYUP · UI 重设计需求文档（交付设计 Agent）

> 本文档只定义**产品定位、功能板块、信息层级与交互语义**。
> **不定义**具体的颜色、字体、字号、间距、圆角、阴影、卡片具体样式与组件尺寸——这些全部由设计 Agent 自由发挥。
> 文中出现的数字（如"三档宽度""3 行截断""6~10 个主干"）是**功能机制参数**，描述的是行为规则，不是视觉规格；视觉呈现方式由设计决定。

---

## 一、产品定义与用途

**产品名**：DAYDAYUP（取"好好学习，天天向上"之意）

**一句话定位**：面向陌生领域系统自学的「AI 探索式知识树沉淀工具」。

**目标用户**：正在跨领域自学的人——典型如转岗到陌生技术领域的从业者、要进入新行业做业务的人。共同特征：对该领域接近零基础、有明确的学习目的（学完要能做事）、讨厌名词轰炸式的科普。

**核心价值**：
1. **先懂你，再教**：输入学习领域或目标（一段自然语言），AI 先提炼「学习档案」（你是谁、学完要干什么、以什么视角学、什么不用学），此后整棵知识树都为这个目标定制。
2. **双模式下探**：任意节点可以「进一步解释」（AI 分层讲透）或「追问」（提出个人疑问，生成专属回答分支），无限层级递归。
3. **像讲义不像词典**：内容先直觉后术语、善用比喻（优先借用学习者已有背景）、长短随内容需要。
4. **无限画布沉淀**：知识以树状卡片形式留在无限白板上，可折叠回溯、可拖拽整理、永不重叠，形成个人可迭代的知识体系。

**产品红线**（设计必须服务的原则）：
- 一切为「系统性自学」服务，不做头脑风暴/娱乐/社交功能；
- 知识结构与可读性优先于视觉花哨；
- 任何时刻用户都不能"迷路"（随时可回主干、随时有全局视野）；
- 等待 AI 时必须有明确、安神的反馈（呼吸感），不能像卡死。

## 三、左侧栏（功能控制区）

左侧栏承载所有"管理类"功能，自上而下分为六个功能块：

### 3.1 品牌
- 产品名 DAYDAYUP + 一句 tagline（"好好学习 · 天天向上 · 从 0 到 1 长出知识树"）。
- 品牌区可自由设计（logo 形态、树/生长意象均可发挥）。

### 3.2 新建知识树（两步 AI 生成）
- **输入区**：多行文本输入，高度随内容自适应增长（封顶后内部滚动）。
  - 引导文案鼓励写"学习目标"而非只写领域名，如："输入学习领域或目标，越具体越定制"。
  - 输入越长越详细，生成的树越定制（因为有档案提炼）。
- **生成按钮**：
  - 空输入时不可用；
  - 生成中变为**停止按钮**（红色语义），点击立即中止，输入内容保留不丢；
  - 生成是两步流程（先"理解你的需求"再"搭建骨架"），耗时约 30~60 秒，画布空态区同步显示进行中提示。
- **生成偏好（可选，三件套）**：
  - 讲解深度：零基础友好 / 系统进阶 / 专业硬核（单选）；
  - 讲解口吻：导师讲解 / 技术文档 / 从业者实战（单选）；
  - 我的背景：一行自由文本（如"平面设计师，会 PS/AI"），AI 打比方时优先取材于此；
  - 三项均可不填，有默认值；设置持久化，对后续所有 AI 输出生效。
  - 需传达"这是可选辅助"的心智，不能喧宾夺主压过输入区。

### 3.3 知识树列表
- 多棵知识树的管理：每项显示**树名（即档案提炼出的领域名）+ 节点总数**；
- 点击树名：切换当前树（画布切换、视口自动适配全局）；
- 每项两个操作：**导出 JSON**（备份）、**删除**（需二次确认，确认文案提示"不可恢复，可先导出备份"）；
- 当前激活树需要有明确的选中态。

### 3.4 数据管理
- **导入知识树**：从本地 JSON 文件导入（文件选择器），导入即成为一棵新树；
- 导入的数据可能携带历史位置信息，画布会自动做无重叠解算（见 6.4）。

### 3.5 设置（可折叠面板）
- API Key（密码型输入）、Base URL、模型名；
- 附说明文字：配置已通过本地 .env.local 自动注入，仅存本地浏览器；
- 此面板偏工程向，视觉上应低调。

### 3.6 旧树自动修复（无 UI 的后台行为）
- 历史遗留的树（没有学习档案、树名是一大段原文）在打开时会自动触发一次档案回填（AI 提炼），树名与根节点会被修复——设计中不需要 UI，但需容忍树名会在打开后几十秒内"自动变短"。

## 四、主画布区（核心学习区）

### 4.1 无限画布本体
- 平移/缩放语义（**Figma 式**，均为硬性交互规则）：
  - 触控板双指滑动（任意方向）＝ 平移画布；
  - 双指捏合 / Ctrl + 滚轮 ＝ 缩放；
  - 空白处按住鼠标拖动 ＝ 平移画布；
  - 抓住任意卡片拖动 ＝ **该卡片连同它的全部子孙（整条分支）一起移动**（详见 6.3）；
- 画布有背景网格（视觉形态由设计定）；
- 缩放范围极大（可缩到看全一棵大树，也可放大到读单卡）。

### 4.2 空状态
- 无任何树：引导语"输入学习领域或目标，生成你的第一棵知识树"；
- 生成中：显示"正在理解你的学习需求并搭建领域骨架…"（动态感）；
- 有树但未选中：提示从左侧选择。

### 4.3 知识节点卡片（产品的核心对象）

**三种卡片类型**（必须有强可辨的视觉区分，具体手法由设计定）：
| 类型 | 含义 |
|---|---|
| 根节点 | 学习领域 + 学习档案摘要（学习目标 / 学习视角 / 不必深入） |
| 标准知识点 | 「进一步解释」或主干生成产生的知识节点 |
| 追问分支 | 用户提问产生的节点，节点标题即原始问题，内容是 AI 的导师式回答 |

**卡片信息结构**（自上而下）：
1. 标题（专业概念或口语化小节标题；过长省略，悬浮可见全文）；
2. 优先级徽章（仅主干层有）：**先学** / **重要** / **按需** 三级——这是学习策略信息，必须一眼可辨、可排序感知；
3. 追问徽章（追问分支专属标识）；
4. 内容摘要：默认截断显示（约 3 行机制）；超过阈值出现「展开全文 / 收起」开关；
   - 展开后卡片在原地变高显示完整内容，**画布其他卡片自动让位，绝不重叠**；
5. 操作行，四个操作（从左到右）：
   - **ⓘ 进一步解释**：AI 把该主题分层讲透，生成 4~8 个子节点；已解释过的卡片该按钮变为完成态且不可重复触发（引导去子节点继续）；
   - **💬 追问**：展开卡片内输入框（见 4.4）；
   - **折叠/展开分支**：仅在有子节点的卡片上出现，需显示**子节点数量**（如 ▾8）；折叠态要有"这里有隐藏内容"的强提示；
   - **学习状态**：单击在 未了解 → 已掌握 → 知识盲区 之间循环；三种状态需极低认知负担可辨（当前用 ○/✓/! + 卡片左侧色条），状态是个人学习进度管理的关键；
6. （生成中）追问输入框或呼吸等待态。

**卡片宽度机制**：按内容长度分三档（短/中/长），长文卡（如追问回答）自动更宽以保障阅读体验——档位视觉宽度由设计定，机制保留。

**卡片操作的整体要求**：操作按钮的含义必须**不需要教学就能看懂**（当前用图标+文字标签混合，设计可重新定义图标语言，但"进一步解释/追问"两个核心动作建议保留文字标签）。

### 4.4 追问输入框（卡片内嵌）
- 点「💬 追问」后，输入框在**该卡片内部、按钮正下方**展开（不是全局浮层）；
- 多行自适应高度；Enter 发送、Shift+Enter 换行、Esc 取消；
- **中文输入法安全**：输入法组词选字的回车不触发发送（硬性要求）；
- 发送后：输入框保持展开，显示**停止按钮**；点击停止立即中止生成，**已输入的文字原样保留**在框内可继续编辑；
- 生成成功后输入框自动收起并清空；生成的追问分支挂在该节点下。

### 4.5 呼吸占位卡片（生成等待反馈）
- 任何 AI 生成（进一步解释/追问）期间，在**发起节点的一侧**出现至少一张占位卡片：
  - 语义："AI 正在生成"，需有持续的呼吸/流光类动态，绝不能静止；
  - 通过一条动态虚线与发起节点相连；
  - 生成完成后被真实卡片无缝替换；
- 这张卡是"产品没有卡死"的唯一画布信号，动态质量要高。

### 4.6 连线
- 父子连线（平滑折线）；**追问分支的连线与标准分支需有区分**（当前：暖色 vs 灰）；
- 正在生成的分支连线带流动动画；
- 连线在低缩放全局视角下仍应可读（树形结构可辨）。

## 五、画布浮层与工具

### 5.1 工具条（画布左上）
- **⟲ 整理布局**：清空所有手动拖拽位置，全树恢复自动树状排列（一键收拾）；
- **⤢ 全局总览**：视口缩放适配到看全整棵树（迷路时的"回家按钮"）；
- 这两个是"防迷路"的关键操作，需常驻、易点。

### 5.2 图例（画布顶部）
- 说明三种卡片类型（根/标准/追问）+ 主要操作含义；
- 常驻但低干扰，可考虑设计成更轻的形式。

### 5.3 小地图 MiniMap（画布右下）
- 显示全树缩略与当前视口框；可拖动/缩放导航；
- 大树时是重要的空间导航工具。

### 5.4 缩放控制（画布左下）
- 放大 / 缩小 / 适配全局 三键（外接纯滚轮鼠标用户的主要缩放入口）。

### 5.5 详情面板（右侧浮层）
- 点击卡片标题或内容区打开（点按钮不算）；
- 内容：**完整知识路径**（根 → … → 该节点，面包屑式，这是"我在哪"的上下文锚点）、标题、完整内容全文、原始追问、元信息（类型/子节点数/学习状态）；
- 可关闭；打开时不应遮挡正在阅读的卡片（位置策略由设计定，当前右上浮层，可重新设计为侧栏抽屉等）。

### 5.6 全局 Toast
- 错误/提示信息，底部浮层，自动消失，可点击关闭；
- 常见内容：API 失败、JSON 解析失败、导入格式错误。

## 六、关键交互行为规范（硬性规则，设计不得违背）

### 6.1 AI 生成等待
- 所有 AI 操作（生成树/进一步解释/追问）期间：发起对象进入等待态 + 呼吸占位卡出现 + 对应按钮变为进行中/停止；
- 必须可中止；中止后一切回到发起前状态（输入内容保留）。

### 6.2 布局自动重排
- 任何结构变化（新增子节点、展开全文、折叠/展开分支、展开追问框）都会触发画布重排；
- 重排动画应平滑（卡片"让位"而非瞬移），用户心智：**画布是活的、有秩序的**。

### 6.3 拖拽 = 移动整条分支
- 抓起一张卡片，它的全部子孙作为刚体跟随；
- 拖拽过程中其他卡片**实时被推开让路**；
- 松手后整条分支及被推开的卡片位置一并持久化（刷新不丢）。

### 6.4 永不重叠（产品红线）
- 无论用户怎么拖拽、展开、导入历史数据，卡片之间**任何时刻不允许重叠**；
- 机制：布局层始终做碰撞解算，卡片间保持间隙；历史/导入的重叠数据自动散开自愈。

### 6.5 折叠与回溯
- 任意分支可折叠（显示隐藏数量）/展开；
- 配合「全局总览」保证随时能从细节回到主干骨架。

### 6.6 学习状态管理
- 三态循环标记（未了解/已掌握/盲区），卡片上有持续可见的状态标识；
- 用于复盘：一眼扫出哪些是盲区（当前红色左边条）。

## 七、数据与状态速览（供设计理解对象，无需 UI）

- **KnowledgeTree**：树名、学习档案（domain/learner/goal/perspective/avoid/原始输入）、根节点、手动位置表；
- **KNode**：标题、内容、类型（root/standard/question）、学习状态（三态）、折叠态、是否已解释、优先级（P0/P1/P2）、子节点列表、原始追问；
- **Settings**：API 配置、讲解深度/口吻、我的背景；
- 持久化：浏览器 localStorage 自动保存 + JSON 文件导出/导入。

---

## 八、设计自由度与边界

**设计 Agent 完全自由**：
- 全部视觉语言：配色体系（含浅色/深色模式的可能性）、字体与字号体系、间距与圆角、阴影与层次、图标语言、卡片形态、动效曲线；
- 侧栏与画布的比例、侧栏可否收起、详情面板的呈现形式（浮层/抽屉/分栏）；
- 品牌表达（树/生长/向上等意象的视觉化）；
- 三种卡片类型、三种优先级、三种学习状态的**具体区分手法**；
- 图例、工具条、小地图的形态与位置优化。

**不可改变的硬约束**：
- 功能清单完整（第三节+第四节所有功能一个不能少）；
- 交互语义（第六节）不变：滑动=平移、捏合/Ctrl滚轮=缩放、拖卡=移分支、永不重叠、可停止、可折叠、IME 安全、展开全文自动让位；
- 信息层级：知识卡片内容 > 操作按钮 > 装饰；
- "先学/重要/按需""未了解/已掌握/盲区""根/标准/追问"这些语义维度的可辨识性；
- 等待反馈（呼吸占位卡）的存在感与动态质量。

## 九、验收清单（设计稿评审用）

- [ ] 新用户第一眼能看懂"这是个学习工具，输入领域开始"；
- [ ] 不看文档能猜出卡片上四个操作各自的含义；
- [ ] 三种卡片类型 / 三种优先级 / 三种学习状态，扫一眼可区分；
- [ ] 折叠态能看出"这里藏着 N 个子节点"；
- [ ] 生成中的等待态有生命感，且能找到停止入口；
- [ ] 全局总览与整理布局入口显眼（防迷路）；
- [ ] 长文卡展开后的阅读体验（宽度、行高）舒适；
- [ ] 深色/浅色（如设计双色）下所有状态语义仍成立；
- [ ] 大树（50+ 节点）缩小时仍能看清结构与优先级分布。
